# Regents CLI handoff

`regents-ai/regents-cli` holds the one `regents` command. On 2026-09-27 the founder chose
Python for it: PyPI `regents-cli`, installed with `uv tool install regents-cli`. The TypeScript
package left `main` the same day; its history is in git and on npm as `@regentslabs/cli` 0.5.0.
The founder also asked for the command set to be designed from how agents use the sites today,
using the old 135 commands only as a reference. The command line follows the sites: it may lag
behind a site, and never holds one up (founder, 2026-09-28).

## Layout

- `src/regents_cli/app.py`: the `regents` root, with one namespace per pinned site.
- `src/regents_cli/runner.py`: builds a site's commands from its description and runs them.
- `src/regents_cli/http.py`: the base-address rule, one request, and how an answer or error
  is read.
- `src/regents_cli/siwa.py`: the agent key, each site's sign-in, and signed requests. Every
  header, covered component, signature parameter and the lifetime come from the signing
  contract in `platforms/siwa/contract.json`, generated by elixir-utils' `siwa` library and
  pinned in `platforms.lock.json` with its fixtures; its sha-256 is the contract id a prepared
  request carries. `tests/test_contract.py` reproduces every signed fixture byte for byte, and
  `scripts/check_siwa_server.py` checks a local `siwa-server` accepts and refuses what it should.
  To move to a new contract: move the `siwa` pin, `make sync`, `make check`, then run that script.
- `src/regents_cli/auth.py`: `regents auth login | status | logout | register`. `register`
  (1.10.15) builds the agent's ERC-8004 listing on Base itself, shows it, and signs and sends
  only that transaction.
- `src/regents_cli/passkey.py`: the agent key locked with a passkey on a Mac (Touch ID), in the
  SIWA agent client's format. `src/regents_cli/passkey.html` is its page.
- `src/regents_cli/browser.py`: pages the person opens (the Touch ID page, the ChatGPT
  sign-in). Since 1.10.7 `regents` prints their address and opens nothing unless run as
  `regents --open-browser …`.
- `src/regents_cli/doctor.py`: `regents <site> doctor`, the same checks for every site.
- `src/regents_cli/output.py`: readable output, `--json`, and the shared error shape.
- `src/regents_cli/next_steps.py`: what every answer and failure says comes next, always one
  or more of done, run, human or a patchbay.help post (founder, 2026-10-13: 1a 2b 3a).
  `output.emit` refuses an answer without steps; failures get theirs from `for_failure`, read
  from the error's status and code, unless the error names its own. An unpaired agent is sent
  to the Account page of the site it called, since each site pairs its own agents.
- `src/regents_cli/errors.py`: the exit codes.
- `src/regents_cli/platforms/`: each site's pinned files, copied by `make sync` from
  `platforms.lock.json`, read at the pinned commit from the site's checkout beside this one
  (`repos/<repository name>`), so only the founder's machine can run it. The lock holds each
  copy's sha256, and `make check` refuses a copy that differs or a folder the lock does not name.
- `src/regents_cli/schemas/commands.v1.json`: the description format.
- `src/regents_cli/check_commands.py`: the description checker (also run by each site).
- `src/regents_cli/techtree/`: `regents techtree`, ported from Techtree 0.3.0 under the
  founder's decisions in `docs/techtree-port.md`. Its commands are in `commands/`, its one
  approval in `approval.py`. `resources/` came from Techtree; the engine bundle, catalog and
  ReleaseCore are now regenerated by the publisher tools in `scripts/techtree/`, never by hand.
- `scripts/stamp_provenance.py`: stamps the wheel with its source commit. The wheel build
  refuses when a packaged file differs from `HEAD`, so run `make check` on a committed tree.
- `verification/features.yml`: the feature map (1.10.15), written by `uv run scripts/features.py
  --write` from the pinned copies and the features listed in that script. `make check` fails
  when it is out of date or a file changed since the last release is in no feature.
- `tests/replays/`: every public read of every site, recorded live by
  `uv run scripts/record_replays.py` and replayed offline by the tests.
- `scripts/check_live.py`: `make release-check` installs the wheel into a new environment, runs
  every public read against the live sites, and checks the Touch ID page is the live sign-in
  server's own.
- `tool_manifests/`: each site's WebMCP tool list, pinned but not shipped;
  `scripts/webmcp_parity.py` reports tools and commands without a partner and never fails.

## Checks

Run `make check`, and `make release-check` before a release, on its own line: piping it into
`tail` in a `&&` chain hides its failure. `make check` prints the seed of the made-up-input
tests, and `make check SEED=<seed>` runs them again the same way. Do not publish, deploy, sign, access production, or move value without the
founder's explicit go.
